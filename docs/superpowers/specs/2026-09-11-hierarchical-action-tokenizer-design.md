# Иерархический токенизатор действий в unified-пространстве — дизайн

Дата: 2026-09-11. Статус: согласовано в чате (Fedorov Artem, агент), ждёт просмотра спеки.
Репозиторий: `Dont4rootMe/vqvae_lattent_actions` (сюда переезжает всё нужное; `tokenizer_arms`, `action_chunks`
(как зависимость), `actioncodec`, `oat`, `beast_tokenizer` — референсы).

## 1. Цель и границы

Обучаемый дискретный токенизатор чанков действий VLA, который:

1. работает в unified action space `bimanual_rotation6d` (119 измерений, 17 семантических групп) и знает про паддинг
   и структуру тела внутри модели, а не видит нули;
2. описывает чанк из T шагов ровно N токенами из словаря размера V; T, N, V — независимые гиперпараметры конфига,
   при этом V ≤ 2048 (не больше различных токенов, чем у FAST);
3. учитывает хронологическую динамику траектории (не pointwise-квантование);
4. не использует состояние робота: на вход только батч действий и маска паддинга;
5. сравним с четырьмя уже посчитанными руками на одном eval-наборе и при равном бюджете бит.

Вне границ этой итерации: переменный T в одной модели (закладываем позиционный код до T_max и маску по времени,
обучение с переменным T — следующая итерация); интеграция в обучение VLA; условие на состояние.

## 2. Данные

* Источник: пакет `action_chunks` (манифест `r0_v2.1-6885099`, смесь R0_v2.1 с RoboDojo, 95 эмбодиментов), чанки
  `fast_action` T×119 в нормализации VLA (q99, [-1, 1]) с масками `fast_action_pad_mask` (T×119, 1 = паддинг) и
  `fast_action_is_pad` (T, 1 = шаг за концом эпизода).
* Маска модели M ∈ {0,1}^{T×119}: M = ¬pad_mask ∧ ¬is_pad[:, None]. Хранится и передаётся именно как матрица,
  произвольный паттерн (целые отсутствующие группы, частично заполненные группы, хвост эпизода).
* Обучение: `WeightedChunkDataset` (эмбодимент ~ веса смеси VLA, старт равномерно), split `train`
  (validation-листы форка исключены, у остальных holdout каждый 50-й эпизод), `samples_per_episode=8`.
* Оценка: общий eval-набор `$BASE/runs/eval_set/eval_set-05d18b2b-val500.npz` (44 642 чанка, ≤500 на эмбодимент),
  тот же, что у FAST/BEAST/ActionCodec/OAT.
* Раскладка групп берётся из манифеста (`Manifest.layout_intervals()`), не хардкодится:
  left_arm.joints [0,8), left_arm.cartesian_position [8,11), left_arm.cartesian_rotation [11,17), left_arm.gripper [17,18),
  left_hand.joints [18,42), right_arm.joints [42,50), right_arm.cartesian_position [50,53), right_arm.cartesian_rotation [53,59),
  right_arm.gripper [59,60), right_hand.joints [60,84), head.joints [84,87), torso.joints [87,92), base.velocity [92,98),
  base.wheel_phase [98,104), left_leg.joints [104,110), right_leg.joints [110,116), base.wheel_joints [116,119).

## 3. Архитектура

Обозначения: T шагов, D = 119 измерений, G = 17 групп, d — ширина модели, K — число запросов на шаг
(K = G групповых + K_free свободных), N — число латентов/токенов, d_z — размерность латента, V — словарь.

### 3.1 Энкодер

1. **Pointwise-эмбеддинг** (T×D → T×D×d). Для позиции (t, j):
   `e[t,j] = (M[t,j] ? W_val · a[t,j] + b_dim[j] : e_pad) + e_group[g(j)] + p_time[t]`,
   где `W_val ∈ R^{d×1}` общий проектор скаляра, `b_dim ∈ R^{D×d}` эмбеддинг измерения, `e_pad ∈ R^d` один обучаемый
   вектор паддинга на все позиции, `e_group ∈ R^{G×d}`, `p_time` — обучаемый позиционный код по времени длины T_max.
2. **Уровень 1, сжатие внутри шага** (T×D×d → T×K×d). K обучаемых запросов `q ∈ R^{K×d}`, одинаковых для всех t,
   делают cross-attention к 119 позициям своего шага. Маска внимания: групповой запрос k<G видит только измерения
   своей группы g=k; свободные запросы видят весь шаг. Позиции паддинга не маскируются (они несут `e_pad`, так
   групповой запрос отсутствующей группы получает токен «группы нет»). L₁ блоков (cross-attn + FFN), затем
   self-attention внутри шага между K токенами.
3. **Уровень 2, динамика** (T×K×d). Self-attention по всем T·K токенам с добавленным `p_time`; L₂ блоков.
4. **Уровень 3, сжатие по времени** (T×K×d → N×d). N обучаемых латентных запросов; Perceiver-блок
   «cross-attention латентов к T·K токенам → self-attention латентов → FFN», повторяется L₃ раз (iterative attention
   по одному и тому же входу). Все attention-блоки pre-LN, GELU, dropout p.
5. Проекция `R^d → R^{d_z}` на каждый латент.

### 3.2 Квантование

Интерфейс `Quantizer.forward(z: N×d_z) -> (z_q, indices: N ints, aux_loss)`, `vocab_size`, `indices_to_embedding`.
По умолчанию FSQ (уровни задаются конфигом, V = ∏ levels; для V=2048 — [8,8,8,4], для 1024 — [8,8,4,4]; STE,
без EMA). Опции за тем же интерфейсом: VQ-EMA (произвольный V, commitment β), LFQ и Gumbel-softmax из текущего
репозитория. Бюджет чанка B = N·log2(V) бит печатается в каждом отчёте (FAST+ ≈ 59 токенов × 11 бит ≈ 650 бит).

### 3.3 Декодер (зеркало)

1. Вход: N квантованных латентов `z_q` + обучаемый эмбеддинг номера латента, проекция `R^{d_z} → R^d`.
2. T×K обучаемых выходных запросов (те же роли: G групповых + K_free свободных, плюс `p_time[t]`): L₃ блоков
   «cross-attention запросов к латентам → self-attention по T·K → FFN».
3. Головы измерений: для (t, j) берётся токен группы g(j) на шаге t, конкатенированный с attention-пулингом
   свободных токенов шага t, → `W_out[j] ∈ R^{2d×1}` (отдельная линейная голова на измерение).
4. Маска на выходе: `â[t,j] = M[t,j] · head_j(...)`; в паддинге выход ровно 0 и он не входит в лосс.
Декодер получает M как вход (при встраивании VLA знает раскладку эмбодимента).

### 3.4 Лосс

`L = MSE_M(â, a) + λ_q · aux_quant`, где `MSE_M` — среднее квадрата ошибки по позициям с M=1 (сумма/число реальных
позиций в батче), `aux_quant` — commitment/entropy квантователя (для FSQ: commitment между z и z_q.detach(), β=0.25).
Взвешивание групп — параметр `group_weights` (словарь группа → вес), по умолчанию выключено. L1 и max-abs — метрики.

## 4. Обучение

* accelerate DDP, 8×H100 через очередь bot (`8gpu`), batch 256/GPU, bf16 autocast, AdamW (lr 3e-4, wd 0.01,
  betas 0.9/0.95), warmup 2000, cosine до 0.1·lr, grad clip 1.0, 300k шагов; один шаг scheduler на шаг оптимизатора
  (`Accelerator(step_scheduler_with_optimizer=False)`, см. ошибку в r07b).
* Оценка на eval-наборе каждые 10k шагов, чекпоинт каждые 5k с resume из `checkpoints/latest.pt`, финальный экспорт
  (`config.json` + веса) и `final_eval.json/md`.
* Логи: tensorboard + `train_log.jsonl`; ClearML убирается (на кластере не используется).
* Первая серия: T=10, N=10, V=2048 (110 бит, прямое сравнение с ActionCodec 0.081); затем N ∈ {5,10,16},
  V ∈ {1024,2048}; d=256, K_free=4, L₁=2, L₂=4, L₃=4, d_z=8 (для FSQ [8,8,8,4] d_z = 4, задаётся уровнями).

## 5. Оценка и отчётность

Метрики (по реальным позициям M=1): RMSE, L1, max-abs (среднее и максимум), всего и по эмбодиментам; число токенов N,
словарь V, бюджет бит; отказов декодирования нет по построению. Отчёты `json` + `md` в формате прошлых рук, чтобы
строка новой модели вставала в таблицу `tokenizer_arms/docs/runs.md` («Итог по четырём рукам»).
Дополнительно: перплексия/использование словаря (есть в репозитории), тест инвариантности к паддингу на eval-наборе.

## 7. Тесты (фиксируют смысл дизайна)

1. Инвариантность к паддингу: изменение значений в позициях с M=0 не меняет токены и выход.
2. Паддинг на выходе: декодер выдаёт ровно 0 там, где M=0, при любом паттерне M (целая группа, часть группы, хвост по времени).
3. Словарь: `quantizer.vocab_size == V` из конфига, индексы в [0, V).
4. Формы: вход B×T×119 с произвольной M → токены B×N, реконструкция B×T×119; для T < T_max тоже.
5. Маска внимания уровня 1: групповой запрос не зависит от значений других групп.
6. Короткое обучение (несколько шагов) на синтетическом манифесте с resume и экспортом; лосс конечен.
7. Отчёт метрик совпадает с `tokenizer_arms.metrics` на одинаковом входе (перенос без искажений).

## 8. Риски и открытые вопросы

* 110 бит на чанк — жёсткий бюджет; выигрыш ожидается от структуры (паддинг, группы, динамика), а не от бит.
  Если N=10/V=2048 не обгоняет 0.081 заметно, сравнение по N и V покажет кривую «бит → ошибка».
* Attention T·K токенов на уровне 2 квадратичен по T·K (при T=10, K=21 это 210 токенов — дёшево; при T=50 — 1050,
  допустимо).
* Групповые запросы с жёсткой маской могут недоиспользоваться для эмбодиментов без этих групп; свободные запросы
  компенсируют. Проверяется по вкладу групповых токенов в eval.
